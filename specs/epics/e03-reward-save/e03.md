# e03: Reward and save (backlog slice S3)

Goal: finishing a room ends with a reward the child collects by touch, and the house remembers what is clean and how
many coins were earned, after the app closes.
Scope in: `SaveFile` (atomic), `Progress` (schema v1), `t32_reward`, reward as data after each room, boot loads and
saves, a corrupt or missing save starts fresh without a crash.
Scope out: title and parent gate, reset-progress control, rub reveal, recorded voice, final art (S4).

## Stories (WSJF order)

| Story | Title | Why here |
|---|---|---|
| e03s01 | SaveFile | Everything else depends on safe storage |
| e03s02 | Progress | The schema: version, clean rooms, coins |
| e03s03 | Template t32_reward | The celebration the child collects |
| e03s04 | Reward in the flow | Rooms lead to the reward, the reward to the map, coins land in Progress |
| e03s05 | Boot keeps progress | Load at start, save at each change, restore the map |

## Decisions

- The save lives in `user://`, local only (ADR-004). `SaveFile` is in the core and takes its path as an argument,
  so the core stays free of game paths.
- Atomic write: write `<path>.tmp`, then rename over the target; the old file survives a crash.
- A star is the carrier of a coin: collecting one adds one coin. There is no separate star total.
- A bad save (missing, unreadable, wrong version, wrong types) gives a fresh `Progress`. Nothing is shown to the child.
- Placeholder star art again; final art is S4.

## Acceptance (epic)

- Clean two rooms, close, open: the map shows both clean and the coin count is kept.
- A truncated save file does not crash and starts fresh.
- Preflight green, `bash scripts/trace_stories.sh --strict` passes, only two `.tscn` files exist.
